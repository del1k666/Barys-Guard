# Dev-стенд BarysGuard

Весь продукт одной командой: PostgreSQL, сервер, консоль, шлюз агентов с mTLS
и пять настоящих агентов. **Не для боевого использования**: пароли известны,
консоль по http, cookie без флага Secure.

## Что нужно

Docker Desktop и Windows PowerShell. Остальное (Python, Go, Node) для запуска
стенда не требуется: всё собирается в контейнерах. Для `.\test.cmd` нужны ещё
Git Bash (шаг с shell-тестами) и локальные окружения тестов, см. ниже.

## Команды

Из корня репозитория, в cmd.exe или PowerShell (не из Git Bash). Обёртки `.cmd`
не требуют менять политику выполнения скриптов PowerShell:

| Команда | Что делает |
|---|---|
| `.\stand.cmd up` | собирает образы, запускает стенд, печатает адрес и пароль |
| `.\stand.cmd status` | состояние сервисов и число агентов по статусам |
| `.\stand.cmd logs [сервис]` | последние 200 строк журнала |
| `.\stand.cmd add-agent [имя] [accounting\|it]` | ещё один агент |
| `.\stand.cmd down` | остановка, данные сохраняются |
| `.\stand.cmd reset` | остановка и удаление всех данных |
| `.\smoke.cmd` | сквозная проверка запущенного стенда: вход, агенты, события `start` от пяти агентов, команда `ping` (код 0 — всё в порядке) |
| `.\test.cmd [-Only web\|agent\|server]` | все тесты репозитория |

После `up`: консоль — http://localhost:8080, логин `admin`, пароль
`stand-admin-password` (значения в `deploy/stand/.env`, он создаётся из
`.env.example` при первом запуске). Агенты регистрируются в течение минуты.

Время: первый `up` на чистой машине около 9–10 минут (три сборки образов,
нужна сеть); повторный `up` с тёплым кешем около 20 секунд; `.\test.cmd`
с готовыми образами и окружением около 100 секунд. Это приблизительные
значения по одному замеру на машине разработчика.

## Из чего состоит

| Сервис | Назначение |
|---|---|
| `postgres` | база |
| `bootstrap` | одноразово: миграции, CA, серверный TLS-сертификат, администратор, группы «Бухгалтерия» и «ИТ», токены регистрации |
| `server` | API и шлюз агентов |
| `nginx` | порт 8080 — консоль, `/api/`, `/health`, `/ready` (`/gateway/` закрыт); порт 8443 — mTLS-шлюз агентов |
| `agent-1`…`agent-5` | настоящие агенты (1–3 в «Бухгалтерии», 4–5 в «ИТ») |

Наружу открыты только `127.0.0.1:8080` и `127.0.0.1:8443`.
`machine_id` агента выводится из имени хоста контейнера, поэтому у разных
агентов он разный, а при перезапуске одного и того же агента сохраняется.

Каждый агент ведёт шифрованный буфер событий в своём томе данных (`events.db` и
ключ `buffer.key`): события сначала записываются туда и только потом уходят на
сервер. `.\stand.cmd reset` стирает и буферы.

## Если что-то не так

| Симптом | Что делать |
|---|---|
| «Docker не запущен» | запустить Docker Desktop |
| «Порт 8080 занят» | освободить порт или задать `STAND_CONSOLE_PORT` в `deploy/stand/.env` |
| Агент не регистрируется | `.\stand.cmd logs agent-1`; если токен потерян, а том агента остался, поможет `reset` |
| Вход отклонён, хотя пароль верный | пароль в `.env` изменили после создания стенда: `reset`, затем `up` |
| Первая сборка долгая | это нормально (около 10 минут), повторные используют кеш слоёв |
| `.\stand.cmd` не запускается в Git Bash | обёртки `.cmd` работают только из cmd.exe и PowerShell |
| `.\test.cmd` показывает проваленный шаг «нет Docker» или «нет sh» | отсутствие Docker или Git Bash `sh` считается ошибкой шага, а не пропуском |
| На машине есть контейнер `deploy-postgres-1` или свой PostgreSQL на 5432 | стенд PostgreSQL наружу не публикует, конфликта портов нет, локальная база не затрагивается |

Отозванный через консоль агент останавливается без перезапуска (код 0);
`add-agent` с тем же именем после `down` подхватывает его прежнюю регистрацию.
