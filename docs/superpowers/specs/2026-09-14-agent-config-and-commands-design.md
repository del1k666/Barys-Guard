# BarysGuard DLP — дизайн 1B (серверная часть): конфигурация агентов, heartbeat и очередь команд

> Продолжение подпроекта 1. Опирается на `docs/superpowers/specs/2026-09-08-dlp-transport-core-design.md`
> и на реализованный план `docs/superpowers/plans/2026-09-08-server-foundation-pki.md`.

## 1. Что уже есть и на что опираемся

План 1A закрыт полностью. Сервер поднимается, внутренний CA выпускает сертификаты, агент
регистрируется одноразовым токеном по CSR, mTLS-личность определяется по серийному номеру
из заголовков nginx, сертификаты продлеваются и отзываются, действия оператора пишутся
в аудит с цепочкой хешей. 58 тестов, контракт в `api/gateway-v1.yaml`.

Чего нет: агент зарегистрировался и замолчал. Он не сообщает о себе, не получает настроек
и не выполняет указаний. Этот документ закрывает разрыв со стороны сервера.

## 2. Границы документа

| Входит | Не входит |
|---|---|
| `POST /gateway/v1/heartbeat` | `POST /gateway/v1/events` — план 1C |
| `GET /gateway/v1/config` | `POST /gateway/v1/artifacts` — план 1C |
| `POST /gateway/v1/commands/{id}/result` | Go-агент — план 1B-agent |
| Модель конфигурации с наследованием по группам | Содержательные DLP-политики — подпроект 3 |
| Очередь команд и её операторский API | Метрики Prometheus, нагрузочный тест — план 1D |
| Вычисляемый статус `offline` | Фоновый сторож пропавших heartbeat — план 1C |

Разделение по планам сохраняется из 1A и не пересматривается здесь.

## 3. Модель доставки

Асимметрия из §8.1 базовой спеки остаётся: события пойдут от агента немедленно (план 1C),
команды забираются на heartbeat. Из трёх возможных форм цикла опроса выбрана первая.

**Принято: heartbeat отдаёт версию конфига и команды; сам конфиг забирается отдельным
запросом только при расхождении версий.** Ответ heartbeat постоянного размера и мал:
при 5000 агентов с интервалом 30 секунд это примерно 167 запросов в секунду, каждый
из которых укладывается в один TCP-сегмент. Тяжёлый документ конфигурации уходит только
тем агентам, чья версия разошлась.

Отвергнуто: вкладывать конфиг прямо в ответ heartbeat при расхождении версий. Ответ
становится переменного размера, а правка корневой конфигурации немедленно порождает
волну из 5000 полноразмерных ответов — ровно тот синхронный всплеск, от которого
§8.2 защищается джиттером.

Отвергнуто: отдельный `GET /commands`. Лишний круг на каждом цикле без выигрыша;
смысл появился бы только при long-polling, который базовая спека отложила осознанно.

## 4. Конфигурация агента

### 4.1 Хранение

```
agent_configs
  id (uuid) · scope (global | group) · group_id → agent_groups ON DELETE CASCADE
  document (jsonb) · updated_by → users ON DELETE SET NULL · updated_at

  CHECK  (scope = 'global' AND group_id IS NULL)
      OR (scope = 'group'  AND group_id IS NOT NULL)
  UNIQUE INDEX ... WHERE scope = 'global'    — глобальная строка ровно одна
  UNIQUE INDEX (group_id) WHERE scope = 'group'
```

Ограничение `CHECK` и оба частичных уникальных индекса обязательны. Без них две
глобальные строки сделают эффективный конфиг зависящим от порядка выборки, а такая
ошибка проявится не при записи, а спустя месяцы на одном агенте из тысячи.

### 4.2 Сборка эффективного документа

Документ агента собирается слиянием по цепочке: глобальная строка, затем строки групп
от корня дерева к группе самого агента. Агент без группы получает только глобальную.

Слияние рекурсивное по словарям; списки заменяются целиком, а не дополняются. Иначе
операция «убрать один путь из исключений» становится невыразимой: дочерняя группа
может только добавлять, но не отменять унаследованное.

Глубина дерева групп ограничена: при сборке цепочки больше 32 уровней сборка
прерывается ошибкой. Дерево строится операторами, и цикл `parent_id` через
`SET NULL` не исключён полностью — бесконечный цикл в обработчике запроса
недопустим.

### 4.3 Форма документа

```json
{
  "transport": {
    "heartbeat_interval_seconds": 30,
    "event_batch_max": 500,
    "event_batch_max_bytes": 4194304,
    "backoff_base_seconds": 1,
    "backoff_max_seconds": 300
  },
  "buffer": {
    "max_bytes": 524288000,
    "max_age_days": 7
  },
  "logging": { "level": "info" },
  "policies": {}
}
```

Значения по умолчанию взяты из §8.2 и §10 базовой спеки. Ключ `policies` зарезервирован
пустым: подпроект 3 наполняет его, не трогая остальные секции и не меняя версию контракта.

Документ валидируется pydantic-моделью при записи. Неизвестные ключи отвергаются:
опечатка `heartbeat_intervall` иначе молча не применится, и разбор такого инцидента
занимает часы.

### 4.4 Версия конфигурации

`config_version` — не счётчик, а детерминированный хеш эффективного документа:
первые четыре байта SHA-256 от канонического JSON (`sort_keys=True`,
`separators=(",", ":")`), приведённые к положительному `int32`.

Счётчик потребовал бы `UPDATE` по всем 5000 агентам в одной транзакции при каждой
правке корневой строки. При хеше правка не пишет ни одной строки в `agents`: каждый
агент обнаруживает расхождение сам на ближайшем heartbeat.

Четырёх байт достаточно: сравниваются только две подряд идущие версии одного агента,
и коллизия означала бы пропуск ровно одного обновления до следующей правки. Цена
ошибки несопоставима с ценой широкого `UPDATE`.

Смысл поля `agents.config_version` меняется: теперь это версия, **применённая агентом**
(та, которую он сообщил в heartbeat), а не желаемая. Расхождение с вычисленной сразу
показывает оператору, кто отстал. Изменение смысла существующего поля отражается
в комментарии модели.

## 5. Эндпоинты gateway

Все три требуют mTLS и используют существующую зависимость `current_agent`.

### 5.1 `POST /gateway/v1/heartbeat`

Запрос:

```json
{
  "agent_version": "0.1.0",
  "config_version": 1734029183,
  "sent_at": "2026-09-14T10:15:30.123Z",
  "buffered_events": 0,
  "buffer_bytes": 0
}
```

Ответ:

```json
{
  "server_time": "2026-09-14T10:15:30.456Z",
  "config_version": 1734029183,
  "heartbeat_interval_seconds": 30,
  "commands": [
    { "id": "...", "type": "ping", "payload": {}, "expires_at": "2026-09-14T11:15:30Z" }
  ]
}
```

Обработчик:

1. Обновляет `last_heartbeat_at`, `last_ip`, `agent_version`, `config_version`
   (сообщённую агентом) и вычисляет `clock_skew_ms = sent_at − время приёма`.
2. Поднимает статус `pending` или `offline` в `active`. Статусы `quarantined`
   и `revoked` heartbeat не меняет — их снимает только оператор.
3. Переводит просроченные команды агента в `expired`.
4. Выбирает до 50 команд в статусе `queued` через `FOR UPDATE SKIP LOCKED`,
   помечает `sent` и проставляет `sent_at`.

`last_ip` берётся из `X-Real-IP`, который проставляет nginx. Адрес из соединения
бесполезен: для приложения это всегда адрес обратного прокси.

`heartbeat_interval_seconds` в ответе берётся из эффективного конфига агента
(`transport.heartbeat_interval_seconds`), а не из настроек процесса. Переменная
`BG_HEARTBEAT_INTERVAL_SECONDS` сохраняется, но её роль сужается до значения
по умолчанию для миграции данных из §11. Двух источников одного числа быть
не должно: иначе правка конфигурации группы не подействует, а причина
обнаружится нескоро.

Дрейф часов записывается, но событие безопасности при превышении порога здесь не
порождается — таблицы событий ещё нет. Это план 1C.

### 5.2 `GET /gateway/v1/config`

Отдаёт эффективный документ и его версию. Поддерживает `If-None-Match`: при совпадении
`ETag` возвращается `304` без тела. Агент опрашивает конфиг редко, но 5000 агентов
после перезапуска сервера сделают это одновременно, и пустой ответ дешевле полного.

### 5.3 `POST /gateway/v1/commands/{id}/result`

Запрос: `{"status": "done" | "failed", "result": {...}}`. Ответ `202`.

- Команда чужого агента отдаёт `404`, а не `403`: различие в ответах позволило бы
  перебором идентификаторов выяснять, какие команды существуют в системе.
- Переход разрешён только из `sent` и `running`. Результат на уже завершённую
  команду возвращает `200` и ничего не меняет — агент имеет право повторить запрос
  после обрыва связи, и повтор не должен затирать первый результат.
- Размер `result` ограничен 64 КБ. Диагностика агента не является каналом передачи
  артефактов, для этого есть `POST /artifacts` в плане 1C.

## 6. Команды

```
commands
  id (uuid) · agent_id → agents ON DELETE CASCADE
  type (ping | refresh_config | collect_diagnostics)
  payload (jsonb) · status (queued | sent | running | done | failed | expired)
  result (jsonb) · created_by → users ON DELETE SET NULL
  created_at · sent_at · completed_at · expires_at NOT NULL

  INDEX (agent_id, created_at) WHERE status = 'queued'
```

Три типа команд, все реализуемы агентом без возможностей подпроекта 2:

| Тип | Назначение |
|---|---|
| `ping` | Проверка живости полного круга: постановка, доставка, результат |
| `refresh_config` | Забрать конфигурацию немедленно, не дожидаясь расхождения версий |
| `collect_diagnostics` | Вернуть состояние offline-буфера, версии, дрейф часов |

Тип — строгое перечисление. Свободная строка позволила бы оператору поставить в очередь
опечатку и узнать об этом только по ошибке от агента через полминуты. Добавление типа
стоит одной миграции.

`expires_at` не nullable: §11 базовой спеки прямо называет команду «изолировать хост»,
доставленную через три недели после закрытия инцидента, аварией. Срок годности по
умолчанию — один час, задаётся при постановке.

`event_queue` из блока 4 базовой спеки здесь не создаётся: она ссылается на таблицу
событий и принадлежит плану 1C.

## 7. Операторский API

Все обработчики под существующей аутентификацией по `X-Api-Key` и пишут в аудит.

| Метод и путь | Роль | Назначение |
|---|---|---|
| `GET /api/v1/config` | operator | Глобальная конфигурация |
| `PUT /api/v1/config` | admin | Заменить глобальную конфигурацию |
| `GET /api/v1/groups/{id}/config` | operator | Конфигурация группы |
| `PUT /api/v1/groups/{id}/config` | admin | Заменить конфигурацию группы |
| `DELETE /api/v1/groups/{id}/config` | admin | Снять переопределение группы |
| `GET /api/v1/agents/{id}/config` | operator | Эффективный документ и его версия |
| `POST /api/v1/agents/{id}/commands` | operator | Поставить команду в очередь |
| `GET /api/v1/agents/{id}/commands` | operator | История команд агента |

Правку конфигурации ограничиваем ролью `admin`: `heartbeat_interval_seconds` в 86400
секунд бесшумно ослепляет весь флот, и это изменение того же веса, что отзыв сертификата.

`GET /api/v1/agents` дополняется вычисляемым статусом: если `last_heartbeat_at` старше
трёх интервалов heartbeat, в ответе отдаётся `offline` независимо от значения в БД.
Строка в базе при этом не меняется — единственный источник истины остаётся один
(`last_heartbeat_at`), а порог живёт в одном месте.

Интервал для порога берётся из **глобальной** конфигурации, а не из эффективной
для каждого агента. Собирать эффективный документ для каждой строки списка значило бы
обходить дерево групп на каждой из тысяч записей; расхождение же между глобальным
и групповым интервалом сдвигает границу на десятки секунд и на смысл ответа не влияет.
Агент, никогда не присылавший heartbeat, сохраняет статус `pending`: он
зарегистрировался, но ещё не выходил на связь, и это не то же самое, что пропавший.

Разграничение по `scope_group_id` применяется ко всем перечисленным обработчикам:
оператор филиала не ставит команды на машины другого филиала.

## 8. Обработка ошибок

| Ситуация | Ответ |
|---|---|
| Сертификат не прошёл проверку, отозван, просрочен | `403`, тело одинаковое во всех случаях |
| Команда не принадлежит агенту либо не существует | `404` |
| Результат на завершённую команду | `200`, состояние не меняется |
| Документ конфигурации не проходит валидацию | `422` с указанием поля |
| Цикл или чрезмерная глубина в дереве групп | `500`, запись в журнал с `group_id` |
| Перегрузка | `429` с `Retry-After` — выдаёт nginx |

## 9. Тестирование

Уровни и фикстуры из 1A: настоящий PostgreSQL через testcontainers, приложение через
`app_client`. Новые таблицы добавляются в `TRUNCATE` фикстуры.

Обязательные проверки безопасности:

- агент не получает команды, поставленные другому агенту;
- просроченная команда не выдаётся и переводится в `expired`;
- результат на чужую команду отвергается с `404`;
- повторный результат не перезаписывает первый;
- отозванный сертификат немедленно перестаёт проходить heartbeat;
- `config_version`, присланная агентом, ни на что не влияет: сервер считает свою;
- оператор вне своей области видимости не ставит команду и не читает конфиг агента;
- роль `operator` не может изменить конфигурацию.

Функциональные проверки: слияние по цепочке из трёх уровней групп; замена списка,
а не дополнение; стабильность хеша при перестановке ключей; `304` по `If-None-Match`;
вычисление дрейфа часов в обе стороны; переход `offline` по порогу в три интервала;
выдача команд под конкурентным доступом через `SKIP LOCKED`.

Контракт `api/gateway-v1.yaml` перевыгружается: он остаётся единственным источником
истины, из которого в плане 1B-agent будет сгенерирован клиент.

## 10. Изменение существующего эндпоинта регистрации

`POST /gateway/v1/enroll` уже возвращает `config_version` и `heartbeat_interval_seconds`,
но берёт первое из `agents.config_version` (всегда 0), а второе — из настроек процесса.
После введения эффективной конфигурации оба значения считаются так же, как в heartbeat:
по документу, собранному для группы, в которую агент попал по токену регистрации.

Иначе только что зарегистрированный агент получил бы версию 0, немедленно обнаружил
расхождение на первом же heartbeat и сходил за конфигом лишний раз — безобидно при
одном агенте и заметно при массовом развёртывании.

Форма ответа не меняется, контракт остаётся совместимым.

## 11. Миграции

Две новые таблицы, один новый комментарий к существующему полю. Начальная глобальная
строка `agent_configs` создаётся миграцией данных со значениями из §4.3: без неё первый
же `GET /config` вернул бы пустой документ, а агент — применил бы пустые настройки.

## 12. Критерии готовности

1. Агент с действующим сертификатом шлёт heartbeat; в БД отражаются время, версия,
   адрес и дрейф часов.
2. Оператор правит конфигурацию группы; агент этой группы на ближайшем heartbeat
   видит новую версию и забирает документ, агент другой группы — нет.
3. Оператор ставит команду; она приходит агенту в ответе heartbeat ровно один раз.
4. Результат команды сохраняется, повтор не меняет сохранённого.
5. Команда, не забранная до `expires_at`, переходит в `expired` и не доставляется.
6. Отзыв сертификата немедленно прекращает обслуживание heartbeat.
7. Все тесты раздела 9 проходят; `ruff` и `mypy --strict` чисты.
8. `api/gateway-v1.yaml` соответствует реализации.
