# BarysGuard DLP — конвейер событий (подпроект 2a)

- **Дата:** 2026-10-05
- **Статус:** на согласовании
- **Область:** доставка событий от агента к серверу: схема конверта, приём и хранение на сервере, шифрованный offline-буфер и отправка на агенте, чтение событий оператором. Сборщики Windows (подпроект 2b) и движки инспекции (подпроект 3) вне области.
- **Опора:** разделы 9 («Конверт события»), 10 («Offline-буфер агента»), блок 2 схемы БД основной спеки `2026-09-08-dlp-transport-core-design.md`.

**Критерий завершения:** после `.\stand.cmd up` пять агентов присылают события канала `agent`, они возвращаются через `GET /api/v1/events`, `.\smoke.cmd` проверяет это и завершается кодом 0; тест «обрыв связи, накопление в буфере, восстановление» подтверждает доставку без потерь и дублей; `.\test.cmd` зелёный.

## 1. Границы

### 1.1 Что входит

| Часть | Содержание |
|---|---|
| Контракт | Конверт события v1 и `POST /gateway/v1/events` в `api/gateway-v1.yaml`; `GET /api/v1/events` для консоли |

| Агент | Пакет `events` (конверт, UUIDv7, интерфейс `Collector`); пакет `buffer` (bbolt, AES-256-GCM, лимиты, вытеснение); отправка в `runner`; встроенный сборщик канала `agent` |

| Не делаем | Почему | Когда |

## 2. Конверт события v1

Форма — раздел 9 основной спеки. Уточнения, принятые здесь:

- `event_id` — UUIDv7, генерируется агентом (своя реализация по RFC 9562 в ~20 строк, зависимость не добавляется).
- `schema_version` — целое, сейчас `1`. Сервер принимает `1`; иное значение отклоняет событие как `unsupported_schema`.
- `channel` — `file | usb | clipboard | network | print | process | agent`. Неизвестное значение — `rejected`.
- `action` — непустая строка до 64 символов; её словарь определяет канал и проверяется в 2b. Для канала `agent`: `start`, `stop`, `config_applied`.
- `severity_hint` — `info | low | medium | high | critical`, по умолчанию `info`.
- `actor`, `process`, `subject`, `labels` — произвольные JSON-объекты; сервер проверяет только тип «объект» и общий размер события (не более 64 КБ). Схемы `subject` по каналам вводятся в 2b.
- `artifact` — необязательный объект `{sha256, size, uploaded}`; в 2a `uploaded` всегда `false`.
- `agent_id` в теле **отсутствует**. Сервер берёт его из клиентского сертификата. Поле, присланное агентом, игнорируется: иначе скомпрометированный агент писал бы события от чужого имени.

Для события канала `agent` `subject` содержит `{"component": "...", "detail": "..."}`.

## 3. Сервер

### 3.1 Таблица `events`

Миграция Alembic. Структура — блок 2 основной спеки:

```
events  PARTITION BY RANGE (occurred_at)
  PK (occurred_at, event_id)
  event_id uuid · agent_id uuid FK agents(id) · schema_version smallint
  channel text · action text · occurred_at timestamptz · received_at timestamptz
  actor jsonb · process jsonb · subject jsonb · labels jsonb
  artifact_sha256 text NULL · severity text
  индекс (agent_id, occurred_at DESC), индекс (channel, occurred_at DESC)
```

Колонки `artifact_id` и `verdict_id` добавятся миграциями подпроекта 3, где появятся их таблицы.

Миграция создаёт партиции на текущий месяц и два следующих, а также `events_default` — страховку на случай события с отметкой вне созданных разделов (часы агента неверны). Событие, попавшее в `events_default`, остаётся читаемым и не теряется.

### 3.2 Менеджер партиций

Функция `ensure_event_partitions(session, months_ahead=2)` создаёт недостающие разделы `events_YYYY_MM` оператором `CREATE TABLE IF NOT EXISTS ... PARTITION OF`. Вызывается при старте приложения и командой `barysguard-admin ensure-partitions`. Отцепление просроченных разделов — вне 2a (политика хранения не определена).

### 3.3 `POST /gateway/v1/events`

- Аутентификация — как у остальных ручек шлюза (`current_agent`).
- Тело: NDJSON, `Content-Type: application/x-ndjson`; одна строка — один конверт. Предел: 500 строк и 4 МиБ (значения из конфигурации `transport.event_batch_max`, `event_batch_max_bytes`); превышение — `413`.
- Каждая строка валидируется отдельно. Результат:

```json
{ "accepted": 480, "duplicates": 15, "rejected": [ { "line": 7, "reason": "unsupported_schema" } ] }
```

- Ответ `202`, если тело разобрано целиком, даже при непустом `rejected`: повторять отклонённое событие бессмысленно, и агент удаляет его из буфера. Нечитаемое тело (не NDJSON) — `400`, агент оставляет пакет.
- Вставка одним `INSERT ... ON CONFLICT (occurred_at, event_id) DO NOTHING`; `duplicates` = принятых строк минус вставленных. `received_at` — время сервера.
- `Content-Length` сверх лимита отвергается до чтения тела.
- Аудит не пишется: события — не действия операторов.

### 3.4 `GET /api/v1/events`

- Роли `admin` и `operator`; видимость ограничивается областью оператора существующим `services/scope`.
- Фильтры: `agent_id`, `channel`, `severity`, `since`, `until`. Пагинация курсорная по `(occurred_at, event_id)`, размер страницы до 200, порядок — от новых к старым.
- Ответ содержит `received_at` и `hostname` агента.
- `GET /api/v1/overview` получает поле `events_24h`.

## 4. Агент

### 4.1 Пакет `events`

- `Envelope` — Go-структура конверта; `NewEvent(channel, action, ...)` заполняет `event_id` и `occurred_at`.
- `Collector` — шов для 2b:

```go
type Collector interface {
    Name() string
    Run(ctx context.Context, emit func(Envelope)) error
}
```

`emit` не блокируется: событие кладётся в канал сборщика с конечной ёмкостью. При переполнении счётчик потерянных событий растёт и фиксируется событием `agent/events_dropped`.

- Встроенный сборщик `agentcollector` порождает `agent/start` при запуске, `agent/stop` при остановке и `agent/config_applied` при смене версии конфигурации.

### 4.2 Пакет `buffer`

Реализует раздел 10 основной спеки:

- Хранилище — bbolt (MIT), файл `events.db` в рабочем каталоге агента, `0600`.
- Шифрование каждой записи AES-256-GCM, случайный nonce. Ключ — 32 случайных байта; хранится через уже существующий `platform.Guard` (DPAPI на Windows, файл `0600` на Linux). Потеря ключа превращает буфер в нечитаемый: он пересоздаётся пустым, факт фиксируется событием `agent/buffer_reset`.
- Ключ записи — монотонный порядковый номер, значение — шифротекст конверта. Порядок FIFO получается обходом по ключу.
- Лимиты: 500 МБ и 7 суток (из конфигурации агента, значения по умолчанию из спеки). Вытеснение при превышении: сначала самые старые записи низкой критичности (`info`, `low`), затем `medium`, затем `high`. Записи `critical` не удаляются никогда; если буфер полон одними `critical`, новые события отбрасываются и учитываются в счётчике потерь.
- Интерфейс: `Append(Envelope) error`, `NextBatch(maxEvents, maxBytes) (Batch, error)`, `Ack(Batch) error`, `Stats() (count, bytes)`. Событие сначала `Append`, и только потом отправляется.

### 4.3 Отправка

В `runner.RunOnce` после heartbeat и команд — `flushEvents`: пока в буфере есть записи и запросы успешны, берётся пакет, отправляется `POST /events`, при `202` вызывается `Ack`. Ответ `rejected` тоже подтверждает пакет целиком. При сетевой ошибке или `5xx` пакет остаётся, действует существующий backoff; при `413` пакет уменьшается вдвое. `buffered_events` и `buffer_bytes` в heartbeat берутся из `Stats()`.

Один проход отправляет не более 20 пакетов, чтобы накопившийся за неделю буфер не блокировал heartbeat и команды.

### 4.4 Транспорт

В `transport.Client` добавляется `SendEvents(ctx, ndjson []byte) (EventsResult, error)`. Остальное поведение — как у соседних методов: mTLS, `StatusError`, `RetryAfter`.

## 5. Проверка

| Уровень | Что проверяется |
|---|---|
| Серверные тесты | Миграция и партиции; приём: принято, дубль, отклонено (схема, канал, размер, не объект); идентичность из сертификата, а не тела; `413`; `400` на не-NDJSON; события вне созданных партиций попадают в `events_default`; чтение с фильтрами, курсором и областью оператора |
| Тесты агента | UUIDv7 (версия, монотонность); шифрование и расшифровка записи, подмена шифротекста даёт ошибку; FIFO; вытеснение по критичности; `critical` не вытесняются; лимит по возрасту; восстановление после потери ключа; `Ack` только после `2xx` |
| Сквозной | Тестовый сервер недоступен, сборщик порождает N событий, сервер появляется, все N доставлены ровно по разу (`e2e_test.go`) |
| Стенд | `smoke.ps1`: после запуска `GET /api/v1/events?channel=agent` возвращает события от всех пяти агентов |
| Контракт | `contract_test.go` сверяет формы запроса и ответа с `gateway-v1.yaml` |

## 6. Риски и решения

| Риск | Решение |
|---|---|
| Рост `events` без политики хранения | Партиции готовы к `DETACH`; политика хранения — отдельное решение, фиксируется в списке открытых вопросов подпроекта 3 |
| Лавина событий после долгого обрыва | Предел 20 пакетов на проход, серверный `Retry-After`, существующий джиттер |
| Часы агента неверны, событие из далёкого будущего или прошлого | Страховочная партиция; значение не отбрасывается |
| Потеря ключа буфера | Пересоздание пустого буфера и событие `agent/buffer_reset`; тихой потери нет |
| Отравленное событие блокирует очередь | Отклонение по событиям, `rejected` подтверждает пакет |
