# BarysGuard DLP — стенд: запуск и проверка одной командой

**Дата:** 2026-10-04
**Статус:** реализовано (стенд, задачи 1–8 плана)
**Предшествующие спеки:** `docs/superpowers/specs/2026-09-08-dlp-transport-core-design.md` (раздел 4.1, подпроект 5 — в части dev-стенда), `docs/superpowers/specs/2026-10-04-web-console-cycle-1-design.md`
**Контракт:** `api/gateway-v1.yaml`

## 1. Цель и границы

Сейчас, чтобы увидеть систему целиком, нужно в трёх терминалах поднять PostgreSQL, задать переменные окружения, применить миграции, создать оператора, выпустить TLS-сертификат внутренним CA, поднять nginx, запустить консоль, вручную выпустить токен и зарегистрировать агента. Ни один из этих шагов не проверяется автоматически, поэтому каждое изменение требует ручной проверки на всём стенде.

Цель: одна команда поднимает работающую систему с живыми агентами, вторая — проверяет, что она работает, третья — прогоняет все тесты репозитория.

**Критерий завершения:** на машине с Docker Desktop и PowerShell после `.\stand.cmd up` консоль открывается на `http://localhost:8080`, вход выполняется известными учётными данными, в списке пять агентов со статусом «Активен» в двух группах, а `.\smoke.cmd` завершается кодом 0.

### 1.1 Что входит

| Возможность | Реализация |
|---|---|
| Стенд целиком в Docker | `deploy/stand/docker-compose.yml`, Dockerfile сервера, агента и консоли |
| Начальное состояние без ручных шагов | команда `barysguard-admin bootstrap-dev` и сервис `bootstrap` |
| Живые агенты | пять экземпляров настоящего Go-агента, регистрируются сами |
| Управление стендом | `scripts/stand.ps1` (`up`, `down`, `reset`, `status`, `logs`, `add-agent`); обёртки `stand.cmd`, `smoke.cmd`, `test.cmd` в корне репозитория запускают скрипты без смены политики выполнения PowerShell |
| Проверка живого стенда | `scripts/smoke.ps1` — сквозная проверка через HTTP API |
| Все тесты одной командой | `scripts/test.ps1` |

### 1.2 Что не входит

| Исключено | Причина |
|---|---|
| Установщики, systemd, MSI, обновление агентов | Подпроект 5 (упаковка) |
| Браузерные e2e-тесты (Playwright) | Дорого в поддержке; `smoke.ps1` покрывает API, страницы покрыты тестами Vitest |
| Генерация нагрузки (сотни агентов) | Отдельная задача; стенд рассчитан на пять агентов, остальных добавляет `add-agent` |
| Linux и macOS как основная платформа скриптов | Основной интерфейс — PowerShell; Docker-часть переносима, скрипты на bash не пишутся (можно добавить позже) |
| Боевая конфигурация | Стенд явно помечен как небезопасный (раздел 6) |

## 2. Состав стенда

| Сервис | Образ / сборка | Назначение |
|---|---|---|
| `postgres` | `postgres:16-alpine` | База; порт наружу не публикуется |
| `bootstrap` | образ сервера | Одноразовая задача: `alembic upgrade head`, затем `barysguard-admin bootstrap-dev` (раздел 3); после завершения выходит с кодом 0 |
| `server` | образ сервера | `uvicorn` на `0.0.0.0:8000` внутри сети стенда (миграции применяет `bootstrap`) |
| `nginx` | сборка `deploy/stand/nginx/Dockerfile` (nginx со статикой консоли) | Порт `8080` (http): консоль, `/api/`, `/health`, `/ready`; `/gateway/` закрыт. Порт `8443` (https, mTLS): только `/gateway/`, правила `X-Client-*` те же, что в `deploy/nginx/barysguard.dev.conf` |
| `agent-1` … `agent-5` | образ агента | Каждый регистрируется своим токеном группы и шлёт heartbeat |

Порядок запуска задают `depends_on` с условиями: `postgres` (healthy) → `bootstrap` (completed successfully) → `server` (healthy по `/ready`) → `nginx` → агенты. Порядок не зависит от скорости машины.

Наружу публикуются только `127.0.0.1:8080` и `127.0.0.1:8443`.

Консоль отдаётся по http намеренно: самоподписанный сертификат у консоли вынудил бы каждого открывающего стенд принимать предупреждение браузера. TLS с проверкой клиентского сертификата остаётся там, где он является частью проверяемого контура, — на шлюзе агентов.

## 3. Начальное состояние: `barysguard-admin bootstrap-dev`

Новая подкоманда существующего CLI. Все действия идемпотентны: повторный запуск ничего не дублирует и ничего не перезаписывает.

1. **CA.** Вызывает `ensure_ca` (`server/barysguard/pki/ca.py`): создаёт каталог CA, если его нет.
2. **Серверный TLS-сертификат** для nginx, подписанный этим CA. Имена: `localhost`, `nginx`, `host.docker.internal`, `127.0.0.1`. Пишется в общий том `tls` (`server.crt`, `server.key`, `ca.crt`). Если файлы есть и до истечения больше 30 дней — не перевыпускается.
3. **Администратор.** Логин и пароль берутся из `BG_BOOTSTRAP_ADMIN_USERNAME` и `BG_BOOTSTRAP_ADMIN_PASSWORD` (значения по умолчанию — в `deploy/stand/.env.example`). Флаг `must_change_password` для этой учётной записи не выставляется, чтобы вход на стенде не требовал лишнего шага. Если учётная запись есть — не трогается.
4. **Группы.** `Бухгалтерия` и `ИТ`.
5. **Токены регистрации.** По одному на группу через `create_enrollment_token` (`server/barysguard/services/enrollment.py`) с `group_id` группы: `max_uses=20` для каждой группы (запас для `add-agent`; распределение трёх и двух агентов по группам задаёт compose). Токены пишутся в общий том `enroll` файлами `accounting.token` и `it.token`. Если файл есть — не пересоздаётся (открытый токен после создания нигде не хранится, поэтому потерянный файл означает `reset`).

Заданный пароль принимает только `bootstrap-dev`: он вызывает слой сервисов (`create_account` в `server/barysguard/services/users.py`) с явным паролем. Команда `create-user` **не меняется**: она по-прежнему выдаёт случайный временный пароль и требует его смены. Команда `bootstrap-dev` отказывается работать, если `BG_STAND=1` не задана: страховка от случайного запуска на боевом сервере.

## 4. Образы

| Образ | Сборка | Особенности |
|---|---|---|
| `server` | `server/Dockerfile`: `python:3.12-slim`, установка пакета без dev-зависимостей | Запускается не от root. Каталоги CA, артефактов и общие тома принадлежат его пользователю |
| `agent` | `agent/Dockerfile`: сборка на образе `golang` версии из `agent/go.mod`, результат — минимальный образ | Запускается не от root. `entrypoint.sh` см. ниже |
| `nginx` (консоль) | `deploy/stand/nginx/Dockerfile` (контекст — корень репозитория): сборка Vite на `node`, статика в `nginx:1.27-alpine` | Конфиг лежит рядом; SPA-подстановка `index.html` для путей без файла |

У каждого образа есть `.dockerignore`. Без него в контекст сборки попадают `server/.venv`, `web/node_modules`, `.git` и сборка занимает минуты.

### 4.1 Вход агента (`agent/entrypoint.sh`)

1. Если в `/var/lib/agent/` нет регистрации, агент **регистрируется**: `barysguard-agent enroll -server https://nginx:8443 -token "$(cat /enroll/$BG_AGENT_GROUP.token)" -ca-file /tls/ca.crt -data-dir /var/lib/agent`.
2. Затем `barysguard-agent run -data-dir /var/lib/agent` дочерним процессом: код возврата 2 («сертификат отозван») превращается в 0, и compose с `restart: on-failure` не поднимает отозванного агента заново; остальные коды пробрасываются, сигналы остановки пересылаются агенту.

**machine_id.** Агент на Linux читает `/etc/machine-id` и без него отказывает (`agent/internal/platform/platform_linux.go`). В контейнере файла нет, поэтому `entrypoint.sh` создаёт его, если он отсутствует: первые 32 символа SHA-256 от имени хоста контейнера. Имя хоста у каждого сервиса своё (`hostname: agent-1` … `agent-5`), значит и machine_id стабилен между перезапусками и различен между агентами. Без этого шага все пять агентов считались бы одной машиной.

Каталог данных агента — именованный том на каждого агента. При `reset` тома удаляются, и агенты регистрируются заново новыми токенами.

## 5. Команды

### 5.1 `scripts/stand.ps1`

| Команда | Действие |
|---|---|
| `up` | `docker compose up -d --build`, ожидание готовности (все сервисы healthy, `bootstrap` завершён), печать адреса консоли, логина и пароля |
| `down` | остановка без удаления данных |
| `reset` | остановка и удаление томов (база, CA, токены, данные агентов); следующий `up` создаёт всё заново |
| `status` | состояние сервисов и число агентов по статусам |
| `logs [сервис]` | журнал |
| `add-agent [имя] [группа]` | поднять ещё одного агента: отдельный контейнер на том же образе |

Скрипт не требует прав администратора и не меняет ничего вне каталога проекта и Docker. Если Docker не запущен, `up` говорит об этом первой строкой и завершается кодом 1, а не показывает трассу compose.

### 5.2 `scripts/smoke.ps1`

Проверяет **запущенный** стенд через HTTP; каждый шаг печатает «ок» или причину:

1. `GET /health` и `GET /ready` на сервере отвечают 200.
2. Вход неверным паролем даёт 401 без уточнения причины.
3. Вход администратором даёт 200 и cookie сессии.
4. `GET /api/v1/overview`: `agents.total` не меньше 5 (агенты, добавленные `add-agent`, не мешают).
5. В течение 60 секунд все пять агентов получают статус `active` (опрос раз в 2 секунды).
6. Агенты распределены по двум группам (3 и 2).
7. Команда `ping` одному агенту: в течение 60 секунд статус команды `done`.
8. Консоль отдаёт `index.html` на `/` и на `/agents/любой-id` (SPA-подстановка).
9. Порт консоли не пропускает поддельную личность агента: `GET /gateway/v1/config` с заголовками `X-Client-Verify: SUCCESS` отвечает 404.

Код возврата 0, если все шаги прошли; иначе номер первого упавшего шага, для которого напечатаны ожидаемое и фактическое. Скрипт не меняет состояние стенда, кроме одной команды `ping`.

### 5.3 `scripts/test.ps1`

Последовательно и с понятным заголовком каждого блока:

1. **web:** `npm ci` (если нет `node_modules`), `typecheck`, `test`, `build`, `licenses`.
2. **agent:** `go vet ./...`, `go test ./...`.
3. **server:** `pytest` (PostgreSQL поднимает сам testcontainers), `ruff check`, `ruff format --check`, `mypy`.

Сводка в конце: что прошло, что нет, общее время. Код возврата 0 только если прошли все блоки; упавший блок не прерывает остальные (видна полная картина). Параметры `-Only web|agent|server` запускают один блок.

Если серверные проверки (`ruff`, `mypy`) в репозитории сейчас красные, это фиксируется отдельным шагом плана и исправляется, а не скрывается флагами.

## 6. Безопасность стенда

Стенд намеренно небезопасен и обязан это показывать:

- Пароль администратора, парольная фраза CA и ключи — фиксированные dev-значения из `.env.example`. Файл `.env` не попадает в репозиторий (уже в `.gitignore`).
- Порты публикуются только на `127.0.0.1`.
- `bootstrap-dev` требует `BG_STAND=1`.
- Cookie сессии без флага `Secure` на стенде допустимо ровно потому, что консоль отдаётся по http на localhost; `BG_COOKIE_SECURE=false` задан только в `deploy/stand/`.
- В заголовке `docker-compose.yml` и в README стенда написано, что файл не для боевого использования.

## 7. Тесты

| Область | Проверка |
|---|---|
| `bootstrap-dev` | Идемпотентность: два запуска подряд дают одно состояние; отказ без `BG_STAND=1`; пароль задаётся только в этом режиме; токены привязаны к группам; серверный сертификат содержит все перечисленные имена и подписан CA |
| Обычный `create-user` | По-прежнему выдаёт случайный временный пароль и требует его смены |
| `smoke.ps1` | Сам является проверкой; его собственная корректность подтверждается запуском на стенде |
| `entrypoint.sh` агента | Проверяется на стенде: у пяти агентов пять разных machine_id и ни одной ошибки регистрации в журнале |

Критерий готовности, помимо раздела 1: `.\stand.cmd reset; .\stand.cmd up; .\smoke.cmd` проходит на чистой машине без единого ручного действия.

## 8. Риски

| Риск | Что делаем |
|---|---|
| Окончания строк CRLF ломают `entrypoint.sh` в Windows | `.gitattributes`: `*.sh text eol=lf`; образ агента проверяет это сборкой |
| Образ `golang` нужной версии недоступен | Версия берётся из `agent/go.mod`; если образа нет, план фиксирует это явной ошибкой сборки, а не подменой версии |
| Первая сборка медленная | Допустимо; повторные сборки используют кеш слоёв. Время первой сборки записывается в README стенда |
| Порт 5432/8080/8443 занят на машине | `stand.ps1 up` проверяет порты до запуска и называет занятый; порты переопределяются в `.env` |
| Токен регистрации потерян, а том агента сохранён | `reset` — единственный поддерживаемый путь; `status` подсказывает его, если агент не регистрируется |

## 9. Уточнения по итогам реализации

- Обёртки `stand.cmd`, `smoke.cmd`, `test.cmd` запускаются из cmd.exe или PowerShell, не из Git Bash. В `.gitattributes` добавлена одна строка `*.cmd text eol=crlf`; остальное репозиторий уже нормализует в LF.
- Время: первый `up` около 9–10 минут (три сборки образов, нужна сеть), повторный около 20 секунд, `.\test.cmd` с тёплыми образами и окружением около 100 секунд.
- Находка при сборке: образ сервера не запускался без `greenlet`; зависимость объявлена как `sqlalchemy[asyncio]` в `server/pyproject.toml`.
- `machine_id` агента выводится из имени хоста контейнера. Точка входа пересылает TERM/INT агенту.
- `bootstrap-dev` отказывается работать без `BG_STAND=1` и без `BG_BOOTSTRAP_ADMIN_PASSWORD`; если файл токена потерян или в базе нет соответствующей строки, токен выпускается заново (самовосстановление, повторный запуск безопасен).
- `test.ps1` считает отсутствие Docker или `sh` из Git Bash проваленным шагом, он виден в итоговой сводке.
- PostgreSQL стенда наружу не публикуется, поэтому чужой PostgreSQL или контейнер на порту 5432 стенду не мешает.
