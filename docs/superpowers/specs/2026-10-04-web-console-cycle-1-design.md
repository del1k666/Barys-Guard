# BarysGuard DLP — веб-консоль, цикл 1: оболочка, вход, обзор, агенты

**Дата:** 2026-10-04
**Статус:** реализовано (цикл 1); проверка на живом сервере не выполнялась
**Предшествующие спеки:** `docs/superpowers/specs/2026-09-08-dlp-transport-core-design.md` (раздел 4.1, подпроект 4)
**Контракт:** `api/gateway-v1.yaml` — единственный источник истины; типы консоли порождаются из него (`npm run types`)

## 1. Цель и границы

Подпроект 4 («веб-консоль») делится на два цикла «спека → план → код». Этот документ описывает первый: оператор входит в консоль, видит состояние парка и управляет отдельным агентом. Серверная часть (`/api/v1/*`) уже готова и покрыта тестами; каркас `web/` содержит API-клиент, сессию и охрану маршрутов, но ни одной страницы.

### 1.1 Что входит

| Возможность | Эндпоинты |
|---|---|
| Вход и выход, принудительная смена пароля | `POST /auth/login`, `POST /auth/logout`, `GET /auth/me`, `POST /auth/password` |
| Обзор парка | `GET /overview` |
| Список агентов с поиском, фильтром и пагинацией | `GET /agents` |
| Карточка агента: сведения, сертификат, история команд | `GET /agents/{id}`, `GET /commands?agent_id=` |
| Команда агенту | `POST /agents/{id}/commands` (`ping`, `refresh_config`, `collect_diagnostics`) |
| Отзыв агента (только admin) | `POST /agents/{id}/revoke` |
| Оболочка и UI-кит | — |

### 1.2 Что не входит

| Исключено | Причина |
|---|---|
| Группы, пользователи, токены регистрации, аудит, редакторы конфигов | Цикл 2 |
| Инциденты, политики DLP и IoC | Движки инспекции (подпроект 3) не построены, показывать нечего |
| Переключение языков RU/KZ/EN | Строки собраны в одном месте, чтобы добавить языки позже без переписывания экранов |
| Сквозные проверки в браузере | После стабилизации экранов |
| Сохранение в приложении тем и настроек | Тема следует за системой |

## 2. Структура и навигация

Оболочка: боковая панель слева (Обзор, Агенты; внизу имя оператора, роль и выход) и контентная область. На узких экранах панель сворачивается в верхнюю полосу с выдвижным меню. Пункты цикла 2 в меню не показываются: мёртвых ссылок нет.

| Маршрут | Экран | Доступ |
|---|---|---|
| `/login` | Вход | открыт |
| `/password` | Смена пароля | вошедший; единственный экран при `must_change_password` |
| `/` | Обзор | вошедший |
| `/agents` | Список агентов | вошедший |
| `/agents/:id` | Карточка агента | вошедший |

Всё, кроме `/login`, закрыто существующим `RequireAuth`.

### 2.1 Файлы

```
web/src/
├── app/            роутер, оболочка (Shell), сессия, RequireAuth
├── components/     UI-кит (раздел 3)
├── features/
│   ├── auth/       Login, ChangePassword
│   ├── overview/   Overview + запрос
│   └── agents/     AgentList, AgentDetail, диалоги команд и отзыва, запросы
├── i18n/           ru.ts — все пользовательские строки
├── lib/            форматирование (есть), разбор параметров URL
└── api/            клиент и типы (есть)
```

Каждый экран получает данные только через собственные хуки в `features/*`, которые вызывают `api` и TanStack Query. Компоненты кита ничего не знают об API.

### 2.2 Состояние в URL

Поиск, фильтр по статусу, группе и номер страницы списка агентов живут в query-параметрах (`?q=&status=&group_id=&page=`). Ссылку на отфильтрованный список можно переслать, кнопка «назад» работает.

## 3. UI-кит

CSS Modules и переменные в `:root`; светлая и тёмная тема через `prefers-color-scheme`. Новых зависимостей нет: лицензионная проверка (`npm run licenses`) остаётся чистой.

| Компонент | Назначение |
|---|---|
| Button | варианты primary, secondary, danger; состояние `loading` |
| Input, Select | подписи, текст ошибки, `aria-invalid` |
| Badge | статус агента и команды |
| Table | заголовки, пустое состояние, адаптация под узкий экран |
| Pagination | по `total`, `limit`, `offset` |
| Modal | подтверждение опасных действий; Esc, ловушка фокуса, возврат фокуса |
| Toast | результат действия |
| EmptyState, ErrorState, Spinner | пустые, ошибочные, загрузочные состояния (Spinner уже есть) |

Доступность: видимое фокус-кольцо, `aria-*` на динамических элементах, управление с клавиатуры.

## 4. Экраны

### 4.1 Вход
Форма логин/пароль. Ошибки сервера показываются понятным текстом (неверные данные, ограничение частоты попыток). После успеха переход на `state.from` или на `/`.

### 4.2 Смена пароля
Показывается при `must_change_password`; до смены других экранов нет (логика уже в `RequireAuth`). Поля: текущий, новый, повтор; проверка совпадения на клиенте, правила сложности остаются за сервером, его сообщение выводится как есть.

### 4.3 Обзор
Карточки из `GET /overview`:
- агенты по статусам (`total`, `active`, `offline`, `pending`, `quarantined`, `revoked`);
- сертификаты, истекающие скоро (`certificates_expiring`);
- активные токены регистрации (`tokens_active`);
- команды: в очереди и неудачные за 24 часа (`queued`, `failed_24h`);
- распределение по версиям агента и по операционным системам.

Карточка агентов ведёт на `/agents` с соответствующим фильтром. Целостность аудита в обзоре не показывается: её выводит экран аудита цикла 2.

### 4.4 Список агентов
Таблица: имя хоста, статус, ОС и версия, группа, последний heartbeat (относительное время), версия агента. Поиск (`q`), фильтры по статусу и группе, пагинация. Строка ведёт на карточку. Пустой результат фильтра и пустой парк различаются сообщением.

### 4.5 Карточка агента
- Сведения: хост, ОС, архитектура, версия агента, группа, IP, расхождение часов (`clock_skew_ms`), версия конфигурации, дата регистрации, теги.
- Сертификат: серийный номер, отпечаток, срок действия, признак отзыва.
- История команд: `GET /commands?agent_id=`, с типом, статусом, временем и результатом.
- Действия:
  - отправить команду (`ping`, `refresh_config`, `collect_diagnostics`): выбор типа, подтверждение, затем тост;
  - отозвать агента: кнопка видна только роли `admin`, действие через модальное подтверждение с названием хоста. После отзыва карточка обновляется.

## 5. Ошибки и права

- 401 обрабатывает существующий `onUnauthorized`: кеш сбрасывается, оператор оказывается на входе.
- 403 и 404 показываются как ErrorState внутри оболочки, а не пустым экраном.
- Сбой сети или 5xx: ErrorState с кнопкой «Повторить».
- Область видимости оператора (scope) обеспечивает сервер: список и карточки содержат только его поддерево. Клиент права не дублирует; по роли скрывается только отзыв, а сервер всё равно проверяет его независимо.
- После мутаций инвалидируются затронутые запросы (карточка, история команд, обзор).

## 6. Тесты

Vitest и Testing Library; сеть подменяется на уровне `fetch`.

| Область | Проверяется |
|---|---|
| Вход | успех, неверный пароль, переход на `from`, принудительная смена пароля |
| Список агентов | фильтры и поиск пишутся в URL и читаются из него, пагинация, пустые состояния |
| Карточка агента | отображение полей, отправка команды, отзыв: подтверждение и отмена, скрытие кнопки для operator |
| Обзор | отрисовка карточек, переход по фильтру |
| UI-кит | Modal (Esc, фокус), Button (loading), Pagination (границы) |
| Ошибки | 403, 404, 5xx, истёкшая сессия |

Критерий завершения цикла: `npm run typecheck`, `npm test`, `npm run build` и `npm run licenses` проходят; оператор против живого сервера доходит от входа до отправки команды агенту.
